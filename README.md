# Tally

회계프로그램의 전체 매입매출장 엑셀 한 개를 읽어 부가가치세 신고 검토용 월별 집계표를 만드는 로컬 데스크톱 앱입니다. 제품과 계산의 기준은 [TALLY_CANON.md v2.0](TALLY_CANON.md)이며, 이 README는 사용 안내입니다.

일반 집계 규칙은 확정되었지만 모든 샘플의 계산을 재현하는 기준까지 확정된 상태는 아닙니다. 샘플의 원본 세액 유지·별도 비율·추가 정산·업체별 산식은 CANON-13에서 구분합니다. 2026-10-07에 확인한 셀 충돌, 업체·파일 변경 후 결과 혼용, 날짜 누락, 인쇄 누락, 계정 예외, 문자열 보존, 복수 원장 시트, 납부 계산 생략 문제는 해결했고, 남은 샘플별 산식 차이는 CANON-11과 CANON-13에 기록되어 있습니다. 아래 설명이 모든 샘플의 일치를 보증하지 않습니다.

## 설치와 실행

Python 3.11 이상이 필요합니다.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e .
python app.py
```

원본 파일은 사용자 PC에서만 처리되며 서버 업로드나 외부 API를 사용하지 않습니다.

테스트를 실행하려면 테스트 의존성까지 함께 설치합니다.

```powershell
python -m pip install -e ".[test]"
python -m pytest
```

`data`, `outputs`, `samples`, `.codex-work`는 업체명과 거래 내역이 들어 있어 추적하지 않습니다. 이 저장소는 공개이므로 실제 거래 자료를 커밋하지 않고, 테스트와 문서에도 실제 업체명·거래처명을 쓰지 않습니다.

## 지원 입력 형식

회계프로그램에서 내려받은 `.xlsx` 또는 `.xlsm` 전체 매입매출장을 지원합니다. 원장 헤더는 시트의 첫 30행에 있어야 합니다. 파일에 기록된 시트 크기 정보가 없거나 실제와 달라도 실제 셀을 기준으로 읽습니다. 필수 열 제목은 구분, 전표일자, 거래처, 품명, 공급가액, 부가세, 합계, 매입/매출 유형, `Code`, 계정과목, 카드사명, 카드번호입니다.

헤더의 공백·줄바꿈은 무시하며, 부가세는 세액, 합계는 합계금액, 매입/매출 유형은 매입매출유형이라는 제목도 허용합니다. `계정코드`는 내부 명칭이며 실제 입력 헤더 별칭은 아닙니다.

전표일자는 Excel 날짜 셀 또는 `YYYY-MM-DD`, `YYYY.MM.DD`, `YYYY/MM/DD` 문자열을 사용합니다. 실제 날짜인 상세 거래만 집계하고 월계·누계·분기 누계·반기 누계·합계 등 집계 행, 반복된 헤더, 제목·공백 행, 이름 없이 금액만 있는 행은 제외합니다. 구분이 매입·매출이거나, 유형·계정이 있거나, 거래처·품명과 금액이 함께 있는 행은 상세 거래로 보며, 이 행의 전표일자가 비었거나 잘못되면 시트와 행을 표시하고 처리를 중단합니다. 금액은 숫자 또는 숫자 문자열이며 쉼표, 음수, 괄호 음수를 허용합니다. 빈 금액은 0으로 추정하지 않습니다. 필수 열이나 금액 형식이 잘못되면 시트와 열 또는 행을 표시하고 처리를 중단합니다.

중복된 `Code` 열이 있으면 `계정과목` 왼쪽의 `Code` 중 가장 가까운 열을 계정코드로 사용합니다. `Code`는 대소문자를 구분하지 않습니다.

샘플 폴더에는 결과 파일만 있어 원본 통합문서의 원장 시트 수를 입증하지 못합니다. 통합문서 한 개를 지원한다는 요구를 원장 시트 한 개라는 영구 제한으로 확정하지 않습니다. 다중 시트 지원이 검증되기 전까지는 필수 열이 모두 있는 원장 시트가 둘 이상이면 한 시트만 처리하지 않고, 해당 시트 이름을 알리며 중단합니다. 원장 시트가 하나인 파일로 다시 내보내 처리하세요.

## 업체 설정

첫 화면의 `새 업체 설정 추가`에서 다음 값을 저장합니다.

- 업체명.
- 146번 표시 명칭인 상품 또는 음식재료.
- 고정자산으로 처리할 계정코드.
- 업체별 계정코드 예외. `코드=분류` 형식을 쉼표로 구분해 입력합니다(예: `899=제조경비`).
- 차량, 거래처, 사업 무관 지출 후보 키워드. 쉼표로 구분하며 거래처·품명·계정명에서 영문 대소문자를 무시하고 찾습니다.

업체 설정은 로컬 `data/companies.json`에 저장됩니다. 담배 거래처 키워드는 기본값으로 저장되며 화면에서 수정할 수 없습니다. 정본의 분류 우선순위는 계정코드 예외, 업체 지정 고정자산 코드, 기본 계정 규칙 순서입니다. 명시한 계정 예외는 담배 자동 분류보다 우선합니다. 담배 분리는 예외가 없는 146 거래에만 적용합니다.

기존 업체 설정을 불러와 편집하는 화면은 없습니다. 같은 업체명으로 새 설정을 저장하면 기존 설정을 대체합니다. 새 처리에서는 이전 판정이 초기화됩니다.

처리 결과는 처리할 때의 파일·업체·업체 설정에 묶이며, 판정 적용과 저장도 그 설정으로 계산합니다. 처리한 뒤 파일이나 업체를 바꾸거나 같은 업체명으로 설정을 다시 저장하면 결과에 `재처리 필요`가 표시되고 판정 적용과 저장이 막힙니다. 이때는 `처리 시작`을 다시 실행하고 불공 판정을 다시 확인하세요. 새 처리를 시작하면 이전 결과를 먼저 지우므로, 처리가 실패하면 오류를 고친 뒤 다시 처리해야 합니다.

## 불공 검토

원본 불공과 과세 중 불공 후보만 검토 화면에 표시됩니다. 후보는 자동으로 불공 확정되지 않습니다.

- 개별 거래에 판정, 불공 사유, 메모를 입력할 수 있습니다.
- 같은 계정코드와 후보 근거를 가진 거래에 판정을 일괄 적용할 수 있습니다.
- 판단 보류, 원본 불공, 신규 불공 후보만 필터링할 수 있습니다.
- 불공으로 확정할 때는 불공 사유 입력이 필요합니다.

## 결과 엑셀

월별표·거래상세·검산은 읽어 들인 원본 금액을 보존합니다. 다음은 현재 일반 모형의 기간 요약 조정입니다. 조정은 거래별·월별로 나눠 하지 않고 선택한 기간 합계에 한 번 적용합니다. 원본 세액 유지나 별도 비율을 쓰는 샘플에 이 산식을 일률 적용하지 않습니다.

- 세금계산서 매입·매출 세액: `ROUNDDOWN(공급가액 합계 × 0.1, 0)`.
- 카드·현영·제로페이 과세 매출의 공급가액: 세 유형의 과세 합계금액을 모아 `ROUNDUP(합계금액 ÷ 1.1, 0)`. 세액은 합계금액에서 이 공급가액을 뺍니다.
- 공제 매입 세액: 세금계산서 조정 세액에 카과·현과·명시된 의제 세액을 더하고, 최종 불공·공통의 원본 세액을 뺍니다. 매입의 카드외는 원본 금액을 사용합니다.
- 고정 매입이 있으면 고정은 원본 금액을 쓰고, 일반 세액은 세금계산서 조정 세액에서 고정의 원본 세액을 뺍니다.
- 매출 건별(기타)은 원본 공급가액과 세액을 사용합니다.
- 납부: 조정된 과세 매출 세액에서 공제 매입 세액을 뺍니다. 선택 입력한 카드매출 세액공제와 예정미환급세액은 이 납부 금액에서 추가로 뺍니다.

`ROUNDDOWN`은 0 방향으로 소수점을 버리고, `ROUNDUP`은 0에서 멀어지는 방향으로 올립니다. 원본 세액과 조정 세액이 달라도 원본값은 변경하지 않습니다. 일반 모형의 포함 관계, 음수 처리 및 빈 구성요소의 계산은 CANON-05~07을 따릅니다. 샘플의 의제·공제율, 추가 정산, 수기 확정액은 CANON-13의 검증 대상으로 남아 있으며 현재 코드가 모두 자동 재현하지는 못합니다.

두 선택 조정액은 빈 입력을 0으로 처리하는 0 이상의 정수입니다. `처리 시작`이 아니라 엑셀을 저장할 때 검증해 해당 저장 결과에 적용하며, 업체 설정으로 쓰지 않습니다. 카드매출 세액공제는 공제율이나 한도를 계산하지 않고 입력액을 그대로 뺍니다. 세금계산서 매입이 없으면 카드외·의제로 공제 매입 세액을 계산하고, 과세 매출이 없으면 매출 세액을 0으로 보고 납부(음수면 환급)와 입력 조정액을 계산합니다.

앱의 `집계 결과` 탭은 원본 집계와 검산만 보여 줍니다. 단수차이 조정, 카드외 역산, 납부는 저장한 엑셀의 `집계표` 수식으로 계산됩니다.

결과 파일에는 다음 시트가 생성됩니다.

- `집계표`는 위쪽 매입, 아래쪽 매출, 불공 차감, 면세, 카드·현영 보조 집계를 월별로 표시하며 금액이 없는 항목은 생략할 수 있습니다. 표와 조정 요약은 서로 겹치지 않게 배치하고, 매출 계정 열이 많으면 인쇄 범위를 넓혀 모두 포함합니다.
- 매입의 카면·카영·현면·현영은 공제 합계에 넣지 않고 세액 열 없이 유형별 보조표로 표시합니다.
- 세금계산서 매출 계정이 여러 개면 전체 세금계산서 매출표 옆에 계정별 공급가액을 나눠 표시합니다. 계정명이 `회사설정계정과목`이면 `수입금액`으로 표시합니다.
- `불공검토`는 후보 근거와 최종 판정, 불공 사유, 메모를 보존합니다.
- `거래상세`는 원본 시트·행, 카드사·카드번호, 계정 분류, 최종 유형 등 재집계에 필요한 값을 보존합니다. 원본·메모·업체명이 `=`로 시작해도 수식이 아닌 문자열로 저장합니다.
- `미분류`는 정본 규칙으로 분류할 수 없는 과세·불공·공통 매입을 표시합니다.
- `검산`은 건수와 금액, 월별 합계, 미분류와 보류 상태를 표시합니다.

## 검산 실패 시 확인

다음 중 하나라도 있으면 검산 완료로 표시하지 않습니다.

- 상세 거래가 한 건도 없음.
- 어느 집계에도 들어가지 않는 매입·매출 유형.
- 매입 또는 매출의 집계 보존 건수, 공급가액, 세액 차이.
- 계정 미분류 거래. 이때 계정 분류 보존 항목도 실패하고, 미분류 거래가 불공·공통이면 원본 과매계 관계 항목도 실패합니다.
- 불공 판단 보류 거래.

상세 거래의 원본 행이 중복되면 검산 이전에 처리를 중단합니다. 건수와 금액 합계, 월별 합계는 `정보` 상태로 표시하며 검산 판정에는 쓰지 않습니다.

`검산 완료`는 읽어 들인 상세 거래의 내부 분류·집계 검사가 통과했다는 뜻입니다. 모든 원본 시트의 완전성이나 출력 엑셀의 조정 수식 계산값·셀 배치·인쇄 범위까지 검증했다는 뜻은 아닙니다. 출력의 정본 준수는 CANON-10~12의 별도 기준으로 확인합니다.

불공 판정을 수정하면 처리할 때의 원본과 설정으로 현재 작업을 다시 계산합니다. 검산 실패 상태의 검토용 엑셀도 사용자가 확인 후 저장할 수 있지만, `재처리 필요` 상태의 결과는 저장할 수 없습니다.

## 알려진 제한사항

- 입력 열을 사용자가 직접 연결하는 자유 형식 매핑은 지원하지 않습니다.
- 홈택스, 회계프로그램, 전자신고와 직접 연동하지 않습니다.
- OCR과 AI 자동 불공 확정 기능을 사용하지 않습니다.
- 원본 거래를 수정하거나 삭제하지 않습니다.
- 거래상세에 직접 분류되지 않은 의제매입세액과 공통매입 배분을 현재 구현이 자동 산정하지는 못합니다. 샘플에는 원본 유형 밖에서 계산·입력한 사례가 있으므로 입력 원천과 확정액의 기준을 검증해야 합니다.
- 플랫폼별 정산, 별도 비율, 택시 경감·감차·복지 등 샘플의 추가 산식은 현재 일반 집계만으로 재현되지 않습니다. 카드매출 세액공제의 공제율·한도, 가산세, 고정자산 매각의 과세표준 분리, 간이과세 계산도 자동으로 하지 않습니다. 제품 의도에서 제외한다고 확정한 항목은 아니며 CANON-13에 필요한 적용 조건을 기록했습니다.
